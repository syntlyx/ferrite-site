REST API

The same API the panel runs on

Everything in the web UI is a call to this API, so anything you do by hand, a script can do too. JSON in, JSON out, served under /api on the panel port.

Auth

All /api/* routes require an API key (header X-API-Key) or a session cookie from POST /api/auth. Set the key in Settings. /api/auth itself is public.

Hot vs restart

Most settings apply live; a few (bind addresses, cache sizes, upstreams, DNSSEC/ECS) are restart-required — the response says which.

Stats & query log

GET /api/stats/summary

Live counters (total / blocked / cached / upstream), from memory.

GET /api/stats/timeseries

24h, 10-minute buckets for the chart.

GET /api/stats/top-domains · top-blocked · top-clients

Ranked lists across retained history.

GET /api/stats/system

Process CPU, memory, network, disk, load.

GET /api/queries

Filterable query log (by client, status, domain, time).

DELETE /api/queries

Clear the stored query history.

GET /api/logs

Recent in-memory server log records (delta cursor + min level).

Clients

GET /api/clients

Clients grouped by name, with their IPs and learned MACs.

GET /api/clients/{ip}/stats

Per-client counters.

GET · POST /api/clients/aliases

List or set a manual name for an IP/MAC.

DELETE /api/clients/aliases/{key}

Remove an alias.

Filtering

GET · POST /api/blocklist/blacklist · whitelist

List or add manual block/allow entries.

DELETE /api/blocklist/blacklist/{domain} · whitelist/{domain}

Remove an entry.

GET /api/blocklist/check/{domain}

Why-blocked: the decision plus which list/rule matched and the exempting whitelist entry.

GET · POST /api/lists

List or add a subscription (URL + name).

PATCH · DELETE /api/lists/{name}

Enable/disable or remove a list.

POST /api/lists/refresh · /api/lists/{name}/refresh

Re-fetch all, or one list.

DNS, tunnels & tools

GET · POST /api/custom-records

List or add a local A / AAAA / CNAME record.

DELETE /api/custom-records/{domain}

Remove a record.

GET · PUT /api/proxy

Selective-routing config: egresses (tunnels) and rules. WireGuard private keys are masked on GET.

GET /api/tools/resolve?name=&type=

nslookup through your own upstreams (any record type).

GET /api/tools/whois?query=

WHOIS via IANA referral.

Monitoring

A Prometheus endpoint for anyone who already runs a monitoring stack — the same counters the built-in dashboard reads, in text exposition format. There is a ready-made Grafana dashboard to go with it.

Quick check 
curl -H 'X-Api-Key: YOUR_API_KEY' http://ferrite.lan/api/metrics
prometheus.yml — scrape config 
scrape_configs:
  - job_name: ferrite
    metrics_path: /api/metrics
    authorization:
      credentials: YOUR_API_KEY
    static_configs:
      - targets: ["ferrite.lan:80"]
Grafana dashboard Download 
Dashboards → New → Import → upload the JSON,
then pick your Prometheus data source. Covers query
rates, cache, egress health, probe RTT, throughput,
rule hits, and process memory.
GET /api/metrics

Prometheus text exposition (version 0.0.4). Same auth as the rest of the API: send the API key as Authorization: Bearer (Prometheus authorization.credentials) or an X-Api-Key header.

What's exported

Query counters by outcome, cache and blocklist gauges, process memory and file descriptors, and per-egress health, probe RTT, traffic, failures, and per-rule hit counters. Per-domain tables are deliberately not exported — their label cardinality is unbounded; egress ids and rule patterns are config-bounded, so they are.

Cheap to scrape

Every sample is read from counters the server already keeps — a scrape takes no locks on the DNS or proxy hot paths, so short intervals are fine.

Settings, auth & updates

GET · PATCH /api/settings

Read or patch config (secrets masked). Restart-required fields are flagged in the response.

GET · POST · DELETE /api/auth

Check session · log in (password) · log out.

GET /api/update/check

Cached check for newer server/web releases.

POST /api/update/server · /api/update/web

Pull and apply a release at runtime.
