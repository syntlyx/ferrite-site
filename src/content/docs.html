Filtering

Block ads, trackers, and worse

Subscribe to any public list (StevenBlack, OISD, AdGuard, Hagezi…) by URL — they all merge into one fast lookup. Override per domain or per device.

Subscription lists

Add/enable/refresh any hosts-file, Adblock, or plain-domain list URL on the Lists page.

Whitelist / blacklist / wildcards

Exact and *.wildcard rules, with a manual allow/deny that wins over lists.

Subscribable allowlists

Subscribe to a community false-positive feed (e.g. anudeepND) — its domains are never blocked. Adblock @@||domain^ exceptions are understood.

Device profiles & default-deny

Give a device its own subset of block/allow lists — or block everything except an allowlist (kid / IoT mode). Local names (PTR, .lan, .local) keep resolving.

Per-client bypass

Let a specific device skip filtering entirely — matched by IP or MAC.

Why-blocked check

Type a domain and see which list or rule matched, and the whitelist entry that exempts it.

Selective routing · the wedge

Route chosen domains through a tunnel

This is what Ferrite adds over a plain ad-blocker. Define an egress (a tunnel), then a rule: a domain — or a whole device — resolves to Ferrite, which forwards the connection through that egress. Everything else stays direct.

Egress backends

direct, socks5, wireguard (paste a .conf), and evasion. Point a SOCKS5 egress at a local Tor (127.0.0.1:9050) to route over Tor.

WireGuard, two backends

Kernel mode (a netlink-managed wg interface, multi-core crypto, no host routing changes) where the capability and module allow it; otherwise boringtun + smoltcp in-process — no TUN device, no root. Either way the tunnel stays warm and DNS for routed names resolves through it.

Per-rule device scope

Apply a routing rule only to selected clients (picked by name from the query log). Empty = all devices.

DPI evasion

The evasion egress splits the TLS ClientHello at the SNI across TCP segments — bytes unchanged, only segment boundaries move.

Fail-closed

If a tunnel is down, a fail-closed rule drops the connection instead of leaking it direct. Toggle per rule.

Wildcard or apex

A plain domain routes it and all subdomains; *.example.com routes subdomains only.

Upstreams & privacy

Where misses go — and what leaks (nothing)

Cache misses leave through an upstream pool. Pick the protocol, send the query over a tunnel, and harden it so the resolver learns as little as possible.

PlainUDP/TCP 53
DoHDNS over HTTPS
DoTDNS over TLS
DoQDNS over QUIC
Through the tunnel

Send a resolver's queries (plain DNS-over-TCP or DoT) through an egress, with direct fallback when the tunnel is down — your ISP sees only WireGuard.

No client-subnet leak

EDNS Client Subnet is stripped from outgoing queries, so the upstream never learns the client's subnet.

DNSSEC requested

The DO bit is set and signatures are forwarded; pair with a validating resolver over DoT/DoH for end-to-end integrity.

Zone routing

Send a suffix (e.g. your .lan or reverse zones) to a specific local resolver.

More

Records, tools, and config

Custom DNS

Local A / AAAA / CNAME records for exact or wildcard names — clean names for internal services.

Tools

Built-in nslookup (any record type, through your own upstreams) and WHOIS, plus the why-blocked check.

Live stats & query log

In-memory summary safe to poll, 24h timeseries, top domains/clients, and a filterable live log.

Debug logging

A verbose-logging toggle (on by default) for diagnosing issues — flip it from Settings, no restart.

Config file

User config: ~/.config/ferrite/config.toml; system-wide: /etc/ferrite/config.toml. The server writes it — the UI is the primary editor, hand-editing is optional.

Everything over REST

Settings, lists, records, rules, egresses, and history are all managed through the API without restarting the resolver.
